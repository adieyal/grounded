# Default Modeling Flow

Use this as the base pattern before applying any overrides.

1. Ask what the model is for.
2. Ask what is in scope and what is explicitly out of scope.
3. Read the evidence in the codebase.
4. Propose the smallest coherent set of units.
5. Ask the user what feels too broad, too thin, or missing.
6. Tighten the model until the boundary is stable.
7. Freeze the slice and move to spec writing or updates.

The default flow should stay lightweight. If the slice needs special handling for type choice or link strategy, use the override pages rather than expanding this page into a full playbook.
