# Scope Boundary Guidance

Treat the scope boundary as a first-class model artifact.

Capture:
- the user outcome
- the slice being modeled
- the intentionally excluded areas
- the evidence that justifies the boundary

Good boundaries are:
- coherent enough to explain in one paragraph
- narrow enough to finish in one pass
- stable enough that the same names keep making sense after refinement

Bad boundaries are:
- “the entire system”
- “everything related to X”
- “all concepts we can find”
- a boundary that changes every time a new noun appears

If the requested slice keeps expanding, stop and ask whether the user wants a wider model or a first-pass subset.
